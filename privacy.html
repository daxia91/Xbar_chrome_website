Xbar 隐私政策

适用版本：v2.4.6 及以后 · 最后更新：2026-11-24

Xbar 是一个运行在浏览器本地的 X（Twitter）网页增强扩展。我们没有账号系统、没有广告、没有统计埋点，也不出售任何数据。本页说明扩展会接触哪些数据、数据存在哪里，以及你如何删除它们。

1. 我们收集什么

数据类型用途存放位置是否离开你的设备
扩展设置（开关、关键词、界面语言等）保存你的偏好chrome.storage.local；若你开启「跨设备同步」，还会写入 chrome.storage.sync仅在你开启 Chrome 同步时，经你的 Google 账号同步
使用统计（每日点赞/发帖/回复/手打字数的计数、称号进度）在面板中展示统计与生成战绩图本地存储否（除非你主动开启下方「加密云备份」）
关注关系缓存（谁关注你、谁与你互关）避免重复请求，加快标签显示本地存储否
X 页面上的公开内容（昵称、头像 URL、帖子文本）在页面上叠加「已关注 / 互关 / AI 倾向」等标签，或在你截图时合成图片仅在内存与本地缓存中处理否（头像图片由 pbs.twimg.com 直接加载）
登录状态标记（读取 X 的 ct0 会话 Cookie）代表你在本机向 X 官方接口查询你自己的关注/粉丝数据仅在内存中使用，不写入存储否，只发送给 x.com / twitter.com 本身，不发给任何第三方

2. 可选功能：加密云备份（默认关闭）

Chrome 在你卸载扩展时会清空本地数据。若你希望「卸载重装不丢统计」，可以主动开启云备份：

  • 开启后，扩展会生成一个随机的 恢复码 作为唯一标识，不收集邮箱、手机号或任何身份信息。
  • 备份内容在上传前用 AES-GCM 端到端加密，服务端（你自己的 Supabase 实例）只保存密文与恢复码索引，无法读取明文。
  • 上传内容仅为第 1 节列出的设置与统计，不包含 X 的 Cookie、令牌、帖子正文或任何他人信息。
  • 关闭该功能后不再上传；删除云端数据的唯一凭据就是恢复码，清空恢复码即等于让云端数据不可用。

3. 我们不做什么

  • 不收集姓名、邮箱、电话、精确位置等个人身份信息。
  • 不记录你的浏览历史，不读取与 x.com / twitter.com 无关的标签页内容。
  • 不使用广告、第三方分析 SDK 或指纹识别。
  • 不出售、不出租、不向第三方共享你的数据（除上述你主动开启的加密备份外）。
  • 不加载远程代码；扩展的全部逻辑都打包在安装包内。

4. 权限说明

权限为什么需要
storage保存设置与统计到本地；跨设备同步使用 Chrome 自带同步。
cookies读取你自己的 ct0 会话标记，用于在本机调用 X 官方接口查询你自己的关注/粉丝数据。不保存 Cookie 内容。
tabs找到已打开的 x.com 标签页以同步登录状态、在面板中打开用户主页。
downloads把你生成的截图、海报或战绩图保存到本地。
alarms定时刷新统计与热榜，避免频繁轮询。
contextMenus在扩展图标的右键菜单里提供「启用 / 停用」开关。
scripting在你打开的 X 页面上注入并更新面板与标注元素。
站点访问：x.com、twitter.com在页面上显示标签、过滤广告与关键词、生成截图。
站点访问：pbs.twimg.com、abs.twimg.com加载头像图片、解析 X 前端接口参数。
站点访问：syndication.twitter.com当页面未打开时，用公开接口读取某个账号的公开资料用于资料卡兜底。
站点访问：news.google.com在你打开热榜功能时抓取公开新闻标题作为灵感词。
站点访问：*.supabase.co仅用于第 2 节的加密云备份（默认关闭）。

5. 数据保留与删除

  • 卸载扩展或清除扩展数据，本地数据即刻删除。
  • 云备份需要你在面板中清空恢复码，或联系我们删除对应记录。
  • 我们不保留任何服务器日志中的内容数据。

6. 儿童隐私

本扩展不面向 13 岁以下儿童，也不会有意收集其任何信息。

7. 政策变更

如数据处理方式发生变化，我们会更新本页顶部的版本与日期，并在扩展更新说明中注明。

Privacy Policy (English)

Applies to Xbar v2.4.6+ · Last updated: 2026-11-24

Xbar is a browser extension that enhances x.com locally. There is no account system, no advertising, no analytics, and we never sell data. This page explains what data the extension touches, where it is stored, and how to delete it.

1. Data we handle

DataPurposeStorageLeaves your device?
Settings (toggles, keywords, UI language)Remember your preferenceschrome.storage.local; chrome.storage.sync only if you enable cross-device syncOnly via your own Chrome sync, when enabled
Usage counters (daily likes, posts, replies, typed characters, title progress)Show statistics and render share imagesLocal storageNo, unless you enable the optional encrypted backup below
Follow-relationship cacheAvoid duplicate requests and show labels fasterLocal storageNo
Public X page content (display name, avatar URL, post text)Render on-page labels and compose screenshotsIn memory / local cache onlyNo (avatars are loaded directly from pbs.twimg.com)
X session marker (ct0 cookie)Query your own follower/following data from X's official API on this deviceMemory only, never persistedNo. Sent only to x.com / twitter.com, never to third parties

2. Optional encrypted cloud backup (off by default)

  • A random recovery code acts as the only identifier. No email, phone number, or identity data is collected.
  • Data is encrypted with AES-GCM end-to-end before upload. The server (your own Supabase instance) stores ciphertext only and cannot read it.
  • Uploads contain only the settings and counters listed above — never X cookies, tokens, post bodies, or other people's information.
  • Turning the feature off stops all uploads.

3. What we never do

  • No collection of name, email, phone, or precise location.
  • No browsing-history collection and no access to tabs outside x.com / twitter.com.
  • No ads, analytics SDKs, or fingerprinting.
  • No selling, renting, or sharing of data with third parties, other than the opt-in encrypted backup described above.
  • No remotely hosted code; all logic ships inside the package.

5. Retention and deletion

Uninstalling the extension or clearing its data deletes local data immediately. For cloud backups, clear the recovery code in the panel or contact us to delete the corresponding record. We keep no content data in server logs.

6. Children

Xbar is not directed to children under 13 and does not knowingly collect their information.

7. Changes

If our data practices change, we will update the version and date at the top of this page and note it in the extension's release notes.
